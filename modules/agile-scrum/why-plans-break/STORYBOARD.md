# Why plans break: storyboard

1. **Two buildings, two plans** ⭐ (scroll story): a wedding hall built to a stable drawing; a citizen portal planned the same way (6 months of requirements, 12 of building); launch-day surprises nobody wrote down (Humphrey's requirements uncertainty); learning late costs more (Boehm: direction reliable, multiplier context-dependent); short feedback loops (Manifesto principle 3); history (Mercury 1960s, Royce 1970 "risky and invites failure", "waterfall" in print by 1976, Manifesto 2001); plans suit known, stable work (PMI).
2. **Learn early or learn late** ⭐ (simulation, `model.ts`): six portal features, each hiding a surprise revealed two weeks after users can first use it; release cadence (once / quarterly / monthly / fortnightly) and automated testing & deployment; timeline of built → found, stats for first user value, surprises after launch, rework and release effort. Lesson: shorter loops cut rework, and pay off fully only when releasing is cheap.
3. **When big launches go wrong** (step-through): FBI Virtual Case File → Sentinel; HealthCare.gov (a big-bang launch, not a "waterfall" story); GST network 2017 (CAG); UPI's 21-bank pilot as the contrast.
4. **Plan up front, or in loops?** (sort).
5. **A fixed 18-month plan** (choice): pilot a thin working slice with real users early.
