# Sources (fact-checked 2026-09-28, before building)

Full notes: scratchpad `agile/m10-facts.md`.

- Ron Jeffries, "Essential XP: Card, Conversation, Confirmation" (30 Aug 2001): "User stories have three critical aspects. We can call these Card, Conversation, and Confirmation."; "This component is the acceptance test."
- Kent Beck, Extreme Programming Explained (1999): "stories" written on index cards.
- Alistair Cockburn (C2 wiki): stories as "promissory notes for future conversation".
- Jeff Patton, User Story Mapping (2014): "Stories aren't a written form of requirements; telling stories through collaboration with words and pictures is a mechanism that builds shared understanding."; "Shared documents aren't shared understanding." (via consistent secondary quotation).
- Connextra (2001) as origin of the "As a…, I want…, so that…" template (Agile Alliance glossary; Mike Cohn). No "original card" wording claimed.
- Bill Wake, "INVEST in Good Stories, and SMART Tasks" (xp123.com, 2003): the six letters and "slice vertically".
- Dan North, "Introducing BDD" (2006, with Chris Matts): "Given some initial context (the givens), When an event occurs, Then ensure some outcomes."; Cucumber (2008).
- Mike Cohn: acceptance criteria are per item, the Definition of Done applies to every item; technical "As a developer" stories as a warning sign; "so that" important but not mandatory.
- Scrum Guide 2020: no "user story"; "Product Backlog items". Job stories: Intercom (named by Alan Klement).
- GIGW 3.0 (NIC/MeitY, 2023): WCAG 2.1 level AA; time limits extendable ("warned before time expires and given at least 20 seconds…").
- The weak stories and scenario are illustrative.
