# Sources: Why review code (fact-checked 2026-10-11)

- Michael E. Fagan, "Design and code inspections to reduce errors in program development", IBM Systems Journal 15(3), 1976.
- Alberto Bacchelli & Christian Bird, "Expectations, Outcomes, and Challenges of Modern Code Review", ICSE 2013 (Microsoft): finding defects is the main motivation, but reviews are less about defects than expected; knowledge transfer, team awareness, alternative solutions; code improvement was the largest comment category (29%), defects fourth (14%).
- Sadowski, Söderberg, Church, Sipko & Bacchelli, "Modern Code Review: A Case Study at Google", ICSE-SEIP 2018: education, maintaining norms, gatekeeping, accident prevention; median change 24 lines; median one reviewer; median latency under 4 hours.
- Capers Jones defect-removal figures: proprietary benchmark data that varies between publications, so not quoted.
