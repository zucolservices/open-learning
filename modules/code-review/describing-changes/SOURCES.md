# Sources: Describing your change (fact-checked 2026-10-11)

- Google Engineering Practices, "Writing good CL descriptions": first line a short, complete, imperative summary that stands alone ("Delete the FizzBuzz RPC…"); body covers the problem, why this approach, shortcomings, links; bad examples include "Fix bug", "Fix build.", "Phase 1".
- Self-review: common practice (not a Google guideline); Google suggests re-reading the description before submitting since changes drift during review.
- GitHub/GitLab closing keywords ("Closes #123") close the issue only when merging into the default branch.
