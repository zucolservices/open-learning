# Sources (fact-checked 2026-10-02, before building)

Full notes: scratchpad `streaming/m09-facts.md`.

- Confluent Schema Registry: compatibility types BACKWARD (default, non-transitive), BACKWARD_TRANSITIVE, FORWARD, FORWARD_TRANSITIVE, FULL, FULL_TRANSITIVE, NONE; upgrade consumers first for BACKWARD, producers first for FORWARD, either for FULL. TopicNameStrategy default (<topic>-value). Wire format: magic byte 0 + 4-byte schema ID (default); header-based 16-byte GUID option from Confluent Platform 8.1.1. Server under the Confluent Community License (client/avro libraries Apache 2.0). JSON Schema compatibilityPolicy STRICT/LENIENT; with STRICT and an open content model, adding an optional field is forward compatible only. Confluent recommends BACKWARD_TRANSITIVE for Protobuf. Data contracts (CEL, JSONata rules; metadata) in Confluent Enterprise / Cloud Advanced Stream Governance (7.4+).
- Avro 1.11/1.12 spec, Schema Resolution: reader default used when the writer lacks a field (error if none); fields only in the writer are ignored; aliases; promotions int→long/float/double, long→float/double, float→double, string↔bytes. Union default: first (matching) branch — use null first, default null.
- Protobuf "Updating A Message Type": never reuse field numbers; reserved; adding/removing fields safe; int32/uint32/int64/uint64/bool compatible (truncation); proto3 optional default since 3.15.
- Apicurio Registry and Karapace (Apache 2.0, Confluent-API compatible; Apicurio rules off by default). AWS Glue Schema Registry: Avro, JSON Schema, Protobuf; DISABLED, NONE, BACKWARD(_ALL), FORWARD(_ALL), FULL(_ALL); free. Azure Event Hubs Schema Registry: evolution for Avro only; Backward, Forward, None; Standard tier and above. Google Pub/Sub schemas: Avro and Protobuf, up to 20 revisions, revision ranges per topic. Redpanda: built-in registry, same wire format, BACKWARD default.
- The Payment schema and proposed changes are illustrative; their compatibility outcomes follow the Avro resolution rules.
