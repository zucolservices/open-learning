# Sources (fact-checked 2026-10-02, before building)

Full notes: scratchpad `streaming/m17-facts.md` (raw pages in `m17/`).

- Flink 2.3: credit-based flow control (1.5); backpressure propagates upstream; busy/backpressured/idle time per second (task-timing based since 1.13), web UI OK/LOW/HIGH at 10%/50%; the bottleneck is the busiest task downstream of backpressured ones; buffer debloating (1.14, off by default, 1 s target); Reactive Mode experimental (standalone). Flink Kubernetes Operator 1.16 autoscaler: per-operator, busy time and source backlog, target utilisation 0.7, parallelism capped at Kafka partitions.
- Kafka 4.3: "the consumer simply falls behind and catches up when it can" (until retention deletes data); records-lag-max from current position; max.poll.records 500; fetch.max.bytes 50 MiB, max.partition.fetch.bytes 1 MiB; partitions cap ordered consumer-group parallelism (share groups since 4.2 lift it without ordering). Kafka Streams num.stream.threads default 1, max parallelism = input partitions.
- Spark 4.2: maxOffsetsPerTrigger; no automatic backpressure in Structured Streaming (DStreams' spark.streaming.backpressure.enabled, default false, legacy).
- KEDA 2.21 Kafka scaler: lagThreshold default 10, activationLagThreshold 0; replicas ≤ partitions unless allowIdleConsumers. AWS Lambda Kafka/MSK provisioned mode (22 Nov 2024), 5 MB/s per poller, OffsetLag. Kinesis on-demand: up to 2× the 30-day peak instantly; On-demand Advantage warm throughput; GetRecords.IteratorAgeMilliseconds / MillisBehindLatest. Event Hubs auto-inflate (up only), Standard partitions fixed. Pub/Sub "Handle transient spikes with flow control"; oldest_unacked_message_age_by_region. Burrow lag evaluation (OK, WARNING, STALLED, STOPPED).
- Flipkart Big Billion Days (Google Cloud blog with Flipkart): traffic ~7× normal; 130B+ messages/day on Pub/Sub, up to 500 TB/day at peak. Hotstar (AWS re:Invent 2019): 1M+ new users per minute, pre-warming, ~90 s reaction. JioHotstar 6.12 crore concurrent viewers (Champions Trophy 2025 final).
- The sale-day model (6,000 events/s base, 7× for 20 minutes, 4,000 events/s per consumer, KEDA-style autoscaling with a 3-minute delay) is illustrative.
