# Sources (fact-checked 2026-09-25)

- Anthropic, "Prompting best practices" (platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices): "Show your prompt to a colleague with minimal context… If they'd be confused, Claude will be too"; XML tags; examples; role in the system prompt; long documents at the top and the query at the end ("up to 30 percent" better on complex multi-document inputs); "Tell Claude what to do instead of what not to do"; dial back aggressive language such as "CRITICAL: You MUST…" because newer models may overtrigger. The overview page puts success criteria and evals first.
- OpenAI, "Prompt engineering" guide (platform.openai.com/docs/guides/prompt-engineering): message roles and the developer message (Identity, Instructions, Examples, Context); Markdown and XML tags to mark boundaries; few-shot examples; "Pinning your production applications to specific model snapshots" and "Building tests and evaluation suites that measure prompt behavior".
- Google, "Prompt design strategies" (ai.google.dev/gemini-api/docs/prompting-strategies): clear and specific instructions, constraints, response format; "We recommend to always include few-shot examples"; keep examples in a consistent format; too many examples can make the model overfit.
- Model outputs: onnx-community/Qwen2.5-1.5B-Instruct (fp16 ONNX, Transformers.js v4), greedy decoding, max 110 new tokens, generated once for all 16 ingredient combinations × 6 emails. The q8 export of this model produced incoherent output, so fp16 was used. Emails, company (Kirana Express) and rules are invented for the exercise. Checks run in the browser (`checks.ts`).
